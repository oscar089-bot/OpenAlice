## What's in this release

### 1. Watcher system (market-condition layer)

The largest addition: a deterministic, LLM-free market-condition engine that
wakes a Workspace Session only when a real price condition becomes true.

- **Evaluator** — pure rule evaluation with no I/O and no clock of its own.
  Supports `price_breaks_level`, `price_crosses_level`, `candle_close`,
  `level_reclaim`, `level_breakdown`, `liquidity_sweep_touched`,
  `price_enters_zone`, `price_approaches_zone`, plus management rules
  (`r_multiple_reached`, `unrealized_pnl_pct`).
- **Candle-close arming** — only CONFIRMED candles can fire a `candle_close`
  rule; a candle that closed at or before the arming time is ignored so
  re-arming never replays history.
- **Poll loop** — one market fetch per distinct pair/asset/timeframe per tick,
  shared across watchers. 5s default cadence, 20s fetch ceiling, re-entrancy
  guard, and exponential backoff on a failing feed.
- **Snapshot provider** — bridges the federated bar layer into watcher terms,
  marks the still-forming tail unconfirmed, and normalizes crypto symbols for
  both OKX (`BASE-USDT`) and Yahoo (`BASE-USD`) namespaces.
- **Persisted state** — armed time, spec fingerprint, last/previous confirmed
  candle, fired-condition history, cooldown, and backoff all survive restart.
  Rewriting an Issue's `watch:` block changes the fingerprint and re-arms with
  a fresh state.
- **Wake prompt** — the plan the woken Session receives, mirroring the
  Vibe-Trading reconfirmation prompt shape.

New files: `src/workspaces/watch/{evaluator,loop,snapshot,schema,store,types,board,wake-prompt}.ts`

### 2. Watcher board (Telegram + Discord)

A persistent, live card surface for every armed watcher.

- **Shared renderer** — `packages/connector-protocol/src/watcher-board.ts`
  renders the card, the requirement bar (`▰▱`), the pulse bar, trigger
  progress, distance-to-trigger, candle tracking, and the candle countdown.
  Shared verbatim between chat surfaces and the desktop UI.
- **Telegram board** — dormant until `/watchers`; one message edited in place,
  with pager (Previous/Next), Details/Collapse, Delete, and Close controls.
  Persists chat id, message id, pager index, and expanded set across restart.
- **Discord board** — persistent cards owned by state, adopted on restart,
  with toggle/delete buttons and a dedicated board channel option.
- **Fix (this release)** — expanding a Telegram card now *replaces* the compact
  card with the full detail panel. Previously it rendered both, stacking the
  whole card above its own detail. Now matches Discord.

New files: `telegram-watchers.ts`, `telegram-board-store.ts`,
`discord-watcher-board.ts`, `discord-board-store.ts`,
`src/services/connector-client/watcher-board-bridge.ts`,
`src/services/connector-client/watch-delete.ts`

### 3. Connector pending-delivery store

An interrupted or failed Agent reply is no longer lost.

- **Pending delivery store** — persists an outbound reply that could not be
  delivered, so it is retried instead of dropped.
- **Turn activity narration** — `OwnerChatActivity.narration` carries the
  turn's latest COMPLETE text block (not the accumulating stream, which would
  flicker as the slot is edited in place). Rendered between header and tool
  meta.
- **Delivery manager** rework — retry, redelivery, and failure accounting.

New files: `services/connector/src/core/pending-delivery-store.ts`,
`packages/connector-protocol/src/turn-activity.ts`

### 4. OKX provider (keyless crypto market data)

- **OKX provider** for OpenTypeBB — keyless crypto quotes and K-lines.
  Historical candles, symbol search, and instrument models.
- **Enabled-vendor resolver** — `src/domain/market-data/enabled-vendors.ts`
  decides which market-data vendors are active.
- **Migration** `0045_default_crypto_vendor` — defaults the crypto vendor.

New files: `packages/opentypebb/src/providers/okx/{index.ts,models/*}`,
`src/domain/market-data/enabled-vendors.ts`,
`src/migrations/0045_default_crypto_vendor/`

### 5. Telegram `/new` — start a fresh phone-desk Session

Owner command to begin a new conversation on demand, without losing the old one.

- **Alice** — `newConnectorDeskSession()` rewrites the desk Issue assignee back
  to `@new-then-resume`, so the next inbound message recruits and claims a fresh
  Session. Refused while a turn is running.
- **Route** — `POST /cli/connector-new-session/:connectorId`.
- **Connector** — `newDeskSession?()` on the adapter context, threaded through
  the delivery manager.
- The previous Session stays **active** and reachable by its `resumeId`.
- Watchers are unaffected: each watcher's Issue keeps its own owner.

New files: `src/server/connector-session.ts`, `src/server/connector-stop.ts`

### 6. Connector desk, headless delivery, and schedule fixes

- **Unbound-claim repair** — repairs an Issue whose Session was never bound.
- **Headless delivery/progress** — output and progress handling fixes.
- **Schedule scanner** — dispatch repair.
- **Connector desk** — delivery and lifecycle repair.

New files: `src/workspaces/issues/unbound-claim-repair.ts`
